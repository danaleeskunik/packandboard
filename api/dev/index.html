מדריך טיול דיגיטלי אישי, ישר מהמערכת שלכם

שולחים לנו את המסמכים שיש לכם: מייל, PDF, Word, Excel או טקסט. מקבלים בחזרה קישור למדריך אישי שנפתח בטלפון, בלי הורדה מהחנות.

למי הדף הזה ומה מקבלים

הדף הזה הוא כלי העבודה של הסוכנות. מי שמכין את הטיול מעלה כאן מהמחשב את החומרים שכבר יש לו: תוכנית, מיילים, אישורי הזמנה. תוך דקה הם הופכים לאפליקציית טיול בטלפון של המטיילים, עם הלוגו שלכם.

קישור למטייליםהמדריך בטלפון: יום אחר יום, מלונות וטיסות, מפות ו-Waze, מזג אוויר ומסמכים. נפתח בלחיצה, בלי הורדה מהחנות.
קישור ניהול לסוכן או למדריךאותה אפליקציה עם כפתור עריכה: משנים שעות ופרטים גם תוך כדי הטיול, ושולחים הודעה למטיילים. לא שולחים אותו למטיילים.

שמרו את הכתובת של הדף הזה. היא אישית לסוכנות שלכם.

ככה זה נראה אצל המטיילים (טיול לדוגמה) · פתיחה בחלון מלא

  1. 1. שולחים מסמכיםאת המסלול, הזמנות וכרטיסי טיסה כמו שהם. אין צורך לסדר או להמיר.
  2. 2. מקבלים קישורהקריאה לוקחת עד דקה. אם משהו לא ברור, הטיול ממתין לבדיקה שלנו לפני שהוא נפתח.
  3. 3. שולחים למטיילהוא פותח, והמדריך נשמר גם לשימוש בלי אינטרנט אחרי פתיחה ראשונה.

נסו עכשיו

יצירת טיול

צרפו את המסמכים ו/או הדביקו טקסט, ולחצו "יצירת טיול". תוך דקה תקבלו קישור לשלוח למטיילים.

הדביקו את מפתח ה-API שקיבלתם, צרפו את המסמכים ו/או הדביקו טקסט, ולחצו "יצירת טיול". המפתח נשלח ישירות לשרת שלנו ולא נשמר בדפדפן.

יש שני מקומות לקבצים. חומרים לבניית הטיול (תוכנית, מיילים, אישורים) נקראים רק כדי לבנות את הטיול ואינם נשמרים. מסמכים לנוסעים (כרטיסי טיסה, רכבת, כניסה למוזיאון, שוברים, ויזות) נשמרים בטיול: הנוסעים מוצאים אותם במסך "מסמכים", וגם בכרטיס של ההזמנה.

1. חומרים לבניית הטיול

נקראים ונמחקים. לא נשמרים בטיול.

אל תשלחו דרכונים או פרטי תשלום. מספרי כרטיס ודרכון שבטקסט מוסרים אוטומטית לפני הקריאה, אבל לא ניתן לסנן אותם מתוך קובצי PDF ותמונות.

2. מסמכים לנוסעים (לא חובה)

נשמרים בטיול. כרטיסי טיסה ורכבת, כניסות, שוברים וויזות. PDF או תמונה, עד 8 מסמכים, עד 8MB כל אחד.

יש לכם נתונים מובנים? שליחה כ-JSON

יצירה ממסמכים

כתובת בסיס: https://pab-api.dana-lees.workers.dev. בכל קריאה: Authorization: Bearer pab_...

curl -X POST https://pab-api.dana-lees.workers.dev/v1/trips/from-documents \
  -H "Authorization: Bearer $PAB_KEY" -H "Content-Type: application/json" \
  -d '{"files": [{"name": "itinerary.pdf", "data": "<base64>"}],
       "text": "אפשר גם טקסט חופשי או מייל מודבק",
       "title": "שם (לא חובה)", "reference": "מספר הזמנה שלכם",
       "brand": {"name": "החברה שלכם", "colors": ["#1F5F6B"]}}'

עד 8 קבצים ו-6MB בסך הכול. נתמכים PDF, .docx, .xlsx, .eml (כולל PDF מצורף), תמונות וטקסט. קבצי .doc ו-.xls ישנים: שמרו כ-docx/xlsx או PDF. התשובה זהה ליצירה מ-JSON ויש בה גם notes (מה הוסק או לא היה ברור) ו-confidence. הקריאה פתוחה עד כדקה. בביטחון נמוך הטיול ממתין לאישור גם אם החשבון מוגדר לפרסום מיידי.

מסמכים לנוסעים

שדה נפרד מ-files: files נקראים כדי לבנות את הטיול ונמחקים. documents נשמרים בטיול: הנוסעים מוצאים אותם במסך "מסמכים", ומסמך עם booking נפתח גם מהכרטיס של ההזמנה. עובד בכל דרכי היצירה (מסמכים, JSON ותבנית), ואפשר להוסיף אחר כך:

"documents": [
  {"name": "כרטיס טיסה הלוך", "data": "<base64>", "kind": "flight", "booking": "LY 395"},
  {"name": "כניסה למוזיאון הפראדו", "data": "<base64>", "kind": "entry"}
]

curl -X POST https://pab-api.dana-lees.workers.dev/v1/trips/k3j9x0ab/documents \
  -H "Authorization: Bearer $PAB_KEY" -H "Content-Type: application/json" \
  -d '{"documents": [{"name": "שובר מלון", "data": "<base64>", "kind": "hotel", "booking": "Hotel Gracery"}]}'

curl -X DELETE https://pab-api.dana-lees.workers.dev/v1/trips/k3j9x0ab/documents/2 -H "Authorization: Bearer $PAB_KEY"
  • kind: flight, train, entry, hotel, visa, car, transfer, insurance, other.
  • booking: טקסט שמופיע בכרטיס ההזמנה, כמו מספר טיסה או שם המלון. בלעדיו המסמך מופיע רק במסך "מסמכים".
  • PDF, JPEG, PNG, WEBP או GIF. עד 8 מסמכים לטיול, עד 8MB כל אחד. במחיקת הטיול נמחקים גם המסמכים.

יצירה מנתונים מובנים, עדכון ומחיקה

יצירת טיול מ-JSON

curl -X POST https://pab-api.dana-lees.workers.dev/v1/trips \
  -H "Authorization: Bearer $PAB_KEY" \
  -H "Content-Type: application/json" \
  -d @trip.json

התשובה (201):

{ "trip_id": "k3j9x0ab", "status": "published",
  "link": "https://packandboard.com/t/#k3j9x0ab.<key>",
  "warnings": [], "review_reason": null }

את link שולחים למטייל כמו שהוא, כולל כל מה שאחרי #.

עדכון טיול

curl -X PATCH https://pab-api.dana-lees.workers.dev/v1/trips/k3j9x0ab \
  -H "Authorization: Bearer $PAB_KEY" -H "Content-Type: application/json" \
  -d '{"patch": {"title": "שם חדש"}}'

הקישור נשאר זהה. המטייל רואה את העדכון בפתיחה הבאה (או ברענון).

מחיקה

curl -X DELETE https://pab-api.dana-lees.workers.dev/v1/trips/k3j9x0ab -H "Authorization: Bearer $PAB_KEY"

סטטוסים

סטטוסמשמעות
publishedהקישור פעיל.
needs_reviewממתין לאישור (החשבון מוגדר לאישור, או שהבדיקות מצאו משהו חריג, למשל יום מחוץ לתאריכי הטיול). warnings מסבירים. הקישור לא מציג כלום עד לאישור.

מבנה הטיול

חובה: title, dates.start ו-dates.end (בפורמט YYYY-MM-DD, עד 60 יום), ו-days עם date ו-title לכל יום. כל השאר אופציונלי.

שדהמה
days[].rowsשורות הפעילות של היום: label (בוקר, ערב...) ו-text.
days[].tip, days[].placesטיפ ליום, ומקומות (נפתחים במפה).
flightsdir (out או back), number, from, to, dep, arr (תאריך ושעה עם אזור זמן).
bookings, packing, tips, emergencyהזמנות, רשימת אריזה, טיפים כלליים ומספרי חירום.
currencyקוד מטבע בן 3 אותיות, למשל EUR.
brandname, logo_url (https בלבד), colors (#RRGGBB). ערכת הצבעים של המדריך נגזרת מהצבע הראשון. בלי צבע נבחר צבע לפי היעד.
referenceמזהה שלכם (מספר הזמנה). לא מוצג למטייל.

טקסט הוא טקסט רגיל. **כך** מדגיש. HTML מוצג כטקסט ולא מופעל.

לא שולחים מספרי דרכון, כרטיסי אשראי או פרטי תשלום. אין בהם צורך במדריך.
